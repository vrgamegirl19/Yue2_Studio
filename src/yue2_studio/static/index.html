EXPERIMENTAL STYLE TRAINING

Build your sound.

Choose your songs, share one style, and train an acoustic LoRA.

Trains acoustic production style from your recordings. It may influence vocal texture, but does not specifically train singer identity or separate vocals from instruments.

Each selected song is split into consecutive chunks across the song—not just its first few seconds. For example, a 3-minute song produces 18 ten-second clips. Any shorter leftover ending is excluded. Each training step learns from one clip, cycling through a shuffled pool; enough steps are needed to visit every clip. Longer clips provide more context but need more VRAM. This does not set the length of songs you generate or alter your original files.

ⓘ Shared style and clip length

Describe the shared sound: instruments, genre, vocal delivery, and production. Every selected song uses the same description. Clip estimates count complete fixed-length clips; shorter tails are excluded. Longer clips will require more training memory.

Choose a folder to inspect its audio. No matching text files are needed.

Train a style LoRA

Uses the saved project selected above, not unsaved form edits. Training joins Studio's GPU queue after existing jobs. Other apps are not managed by this queue.

ⓘ How much training?

Defaults to 2,000 updates, not 2,000 passes through every song. Each step learns from one clip. Use 20 steps only for a short technical smoke test. More steps can strengthen the effect, but excessive repetition can overfit and damage musical variety. Loss alone cannot tell you whether it sounds better.

ⓘ How strongly does it learn?

The peak update size; training warms up then tapers it. Start at 0.0001. Larger values can learn faster but become unstable or spoil the sound; smaller values may need more steps. There is no universal safe cutoff. Non-finite loss or gradients stop the run.

ⓘ How much can it remember?

Rank controls adapter capacity and memory use. Start at 8. Higher ranks produce larger files and can overfit a small collection. This version trains acoustic attention only; it does not retrain the song composer or guarantee singer identity.

ⓘ Checkpoints and stopping

Defaults to saving an intermediate adapter every 500 steps to audition later. Frequent saves use more disk space. Cancel waits for a safe boundary and saves completed training updates; closing Studio may force-stop after 10 seconds. Existing checkpoints survive. These adapter files are for inference, not exact optimizer-state resume.

ⓘ Models, caching, and the first run

Uses the local YuE2 and VAE folders from Models & runtime, independently of the inference backend. Requires a BF16 NVIDIA GPU; actual training memory use is still experimental. All selected audio clips are encoded first, even for a 20-step test. The cache is reused when source audio, VAE identity, and clip settings match. Original songs and model weights are never overwritten.

Start with the 20-step smoke test. No GPU training starts until you queue it.

ⓘ Trigger phrase

A distinctive phrase to associate with your artist. Future preparation will combine it with the shared style. Saving this setup does not train it yet.

ⓘ Lyrics are required for this new workflow

Choose the naming convention used by your folder. Each audio filename must have an exact matching text filename, without its audio extension. UTF-8 text only, up to 64 KB per song. Plain .txt files are treated as lyrics only when you explicitly choose that option; style-only files are not lyrics. Include complete words with section tags, then check each preview against the recording. We do not rename or overwrite source files.

ⓘ Shared style and full songs

Keep lyrics separate from this description. Uses complete 30–360 second songs, not the acoustic trainer’s short clips. No model quality, encoder compatibility, or voice identity has been verified by this scan.

Scanning and saving do not start a GPU job.

Saved artist setups

Train an Artist LoRA

Uses the saved setup selected above, not unsaved edits. At least two 30–360 second songs; the last selected song is held out for validation. Whole songs are used without silent clipping. Reference songs make up approximately half of training examples.

ⓘ Steps

Optimizer updates, with two song examples per update. More steps can overfit, not just improve. Try 20 for a technical smoke test; it is not a quality test. No reliable ETA until the first GPU run.

ⓘ Rank

Adapter capacity. 64 follows the community recipe; lower ranks use less training memory but may learn less detail.

ⓘ Learning rate

How aggressively weights change. Default 0.0001 with warmup. Higher values can damage output or cause unstable loss. If that happens, try a lower value.

ⓘ Checkpoints

Keeps intermediate adapters so you can compare training lengths later. More frequent saves use more disk space. These are adapter snapshots, not exact optimizer-resume files.

ⓘ Timing methods

MMS forces every English lyric word onto the separated vocals. Whisper-assisted uses fine-tuned Demucs and Whisper large-v3 to recognize words, match them to your lyric file, and estimate missing positions. Only recognized word timing contributes to training; the full lyric text still conditions every song. A timing JSON is saved for review in the Library run. Whisper large-v3 weights download on first use.

ⓘ Lyric alignment weight

0.08 follows the community recipe. 0 skips all timing preparation and timing loss, regardless of the selected method; full lyrics still condition training. Higher values can overemphasize imperfect timestamps. MMS uses every aligned word; Whisper-assisted excludes estimated timestamps from the timing loss.

Uses Studio's shared queue. Progress, logs, cancellation, and saved checkpoints appear in Library → Open run. Cancellation waits for a safe boundary; separation/alignment of a full song can take time.

QUICK START
Welcome to your studio.
Make an original song
Describe the sound in Style, add lyrics with [Verse] and [Chorus] tags, then choose Create song. Full mode creates melody and harmony before audio. Plan only creates an editable score without rendering audio.
Give a melody a new sound
Choose Create a cover and upload a recording. Transcribe it, then use Review melody in the completed run. You can also import native ABC directly. Check the score and use Prepare melody to remove chords, keeping both melodic voices by default. Enter the target style and lyrics, then create your cover. Full mode can keep the score’s harmony too.
Write with an LLM
Open LLM Runner, choose a provider, enter an API key if needed, and refresh the model list. Custom model IDs are supported. Test the connection, describe your idea in the writing room, and review the editable draft before applying it. You can refine the current lyrics or generate only a style.
Tags & timing
[Verse] and [Chorus] are the official example’s section cues. Other section tags are editable text cues, not guaranteed control tokens. Put vocal delivery, instruments, mood, language and intended BPM in Style. Yue2 has no exact-duration slider or singer-cloning input.
Closing Studio
Closing the last Studio tab stops the server after a 15-second grace period. Refreshing or keeping another tab open keeps it running. Active songs, batches and writing requests finish before automatic shutdown. To return, use Start Yue2 Studio.bat.
Your work stays organized
Each GPU job uses a fresh folder in runs/studio. The library keeps audio, scores, exact requests, token arrays, latents, logs and provenance. Cancel stops that job’s worker. Interrupted jobs need a fresh run. Local draft autosave and exported project JSON exclude API keys. Save a project to make a portable backup; original recordings remain in this workspace.
Local LLMs & memory
Use LM Studio, Ollama, or a custom OpenAI-compatible server for local models. Start that server and load a text model before connecting. If it shares your music GPU, unload its model before a large music run. Ollama requests use keep_alive=0 to release the model after writing.
